# 执行任务工作流

基于 plans 目录下的计划文档驱动本地开发流程。

## 触发条件

输入路径包含 `plans` 时自动触发

## 流程

### 1. 准备分支

从计划文档路径提取需求编号和任务名，创建本地分支：
- 示例：`docs/plans/UAC-123/01-用户列表.md` → `local/UAC-123-01-用户列表`

```bash
git checkout -b local/<需求编号>-<任务名>
```

### 2. 执行任务

1. 读取计划文档
2. 在 local 分支上完善计划文档内容（补充细节、调整方案）
3. 按计划文档要求开发，可任意 `git commit`（存档点：`WIP: <简述>`）
4. **禁止推送 local 分支到 remote**

### 3. 验收

- 开发完成后通知用户验收
- 用户确认通过后继续步骤 4
- 如有问题，继续在 local 分支修复

```bash
git checkout feature/<需求编号>-xxx
git merge --squash local/<需求编号>-<任务名>
git commit -m "feat(<需求编号>): <任务汇总>"
git branch -D local/<需求编号>-<任务名>
```

### 4. 更新状态

**计划文档：**
- 标记 `- [x] 已完成`
- 追加变更文件表格

**overview.md（如存在）：**
- 更新计划分解表格状态为 ✅ 完成
- 追加变更文件到汇总

## 异常处理

| 场景 | 处理 |
| ---- | ---- |
| 中途中断 | 保留 local 分支，下次继续 |
| 合并冲突 | 手动解决后 git add + git commit |
