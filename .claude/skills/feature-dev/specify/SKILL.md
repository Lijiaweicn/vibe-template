# Feature Dev 需求产出

基于 explore 阶段产出的 README，拆分任务并生成 task 文件骨架。

## 前置条件

explore 阶段已完成，`docs/feature/README.md` 已存在（含需求标识、核心功能、验收标准）。

## 流程

### 1. 读取已有 README

读取 `docs/feature/README.md`，提取：
- 需求标识
- 核心功能概述
- 验收标准
- 待确认项

### 2. 拆分任务

根据需求内容拆分任务。

**任务分层标准**：

判断依据：用户能否单独验收这个节点。

| 是大节点（README 层） | 是子任务（task 内拆分） |
|---|---|
| 登录表单 — 用户能看到完整的登录功能 | 验证码组件 — 用户不单独验收它 |
| 列表筛选 — 用户能操作筛选功能 | 筛选参数序列化 — 实现细节 |
| 报价保存 — 用户能保存并看到结果 | domain 模型构建 — 底层步骤 |

大节点出现在 README 的任务列表中，子任务仅在 task 文件内声明或开发中动态产生。

**拆分原则：垂直切片优先**

每个大任务节点是一个**独立可验证的用户可见功能增量**，做完即可独立验证。

| 正确（垂直切，按功能） | 错误（水平切，按技术层） |
|---|---|
| 报价表单 - 基础字段录入与保存 | 建立报价表单 domain 模型 |
| 报价表单 - 大客户特殊定价显隐 | 开发报价表单 UI 视图 |
| 报价列表 - 筛选与排序 | 写报价表单测试 |

**凝聚度检查**：

- **独立可验证**：做完这个任务，用户/QA 能看到一个完整的功能点
- **纵向穿透**：涉及该功能所需的全部层（domain → view → test），但不涉及其他功能
- **禁止按技术层拆分**：不要把"写 model"和"写 view"分成两个大节点
- **功能不跨任务**：如果一个功能做完后才能看到效果，它们应该合并；如果 Todo 超过 10 项，考虑拆出子任务

**任务文件命名**：用 slug 命名，文件名即 ID。

**slug 定义**：小写英文单词用短横线连接，如 `login-form`、`api-auth`、`forgot-password`。禁止中文、驼峰、空格。

生成 `<slug>.md` 文件，如 `login-form.md`。

**任务依赖声明**：每个 task 文件头部用 frontmatter 声明依赖：

```markdown
---
depends: [前置任务slug1, 前置任务slug2]
---
```

无依赖时省略 frontmatter 或写 `depends: []`。

**task 文件模板**：

```markdown
---
depends: []
---
# <任务目标>
<!-- 一句话：这个任务要达成什么效果 -->

## 待解决
<!-- 阻塞项：未想通的技术方案、未确认的外部依赖等 -->
<!-- 无则留空或删除此节 -->

## 已确定
<!-- 已敲定的决策、接口、数据结构 -->

## TODO
- [ ] 步骤1
- [ ] 步骤2

## 验收清单
- [ ] 可观测的用户行为1
- [ ] 可观测的用户行为2
```

**验收清单**：每个任务必须包含验收清单。
- **此阶段为粗粒度描述**，列出功能点级别的验收项（如"登录表单能正常提交"）
- implement 阶段按需深化为具体用户可见场景（如"输入非法邮箱后点击保存，显示红色错误提示"）
- 覆盖核心路径即可，边界情况和异常场景留待 implement 深化时补充

### 3. 更新 README

在 README.md 的"任务列表"部分填充分解结果：

```markdown
## 任务列表
- [ ] [slug-1](slug-1.md)
- [ ] [slug-2](slug-2.md)
```

**注意**：task 文件链接格式为 `[slug](slug.md)`，实际文件名即 `slug.md`。只更新任务列表部分，不修改 explore 阶段产出的需求描述内容。

### 4. 用户确认（必须暂停）

**这是必须暂停的硬性步骤，严禁跳过。**

展示完整的拆分方案（README 任务列表 + 所有 task 文件）后，明确向用户提问：

1. "以上是拆分方案，是否有内容需要补充或调整？"（可合并/拆分任务、调整 Todo 步骤、补充待解决内容）
2. 用户确认内容无误后，再问："是否进入阶段 3（逐项开发）开始实现第一个任务？"

**用户未明确同意前，禁止进入阶段 3。** 如果用户提出了调整，修改后重新展示并再次确认。

## 门禁条件

- [ ] README.md 已存在且包含需求标识（由 explore 产出）
- [ ] README.md 的任务列表已填充
- [ ] 每个 task 文件包含 depends + 验收清单 + TODO
- [ ] 任务拆分符合垂直切片原则（每个任务是独立可验证的功能增量）
- [ ] 用户已确认拆分方案
