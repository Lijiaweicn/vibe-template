# 计划执行工作流

基于 plans 目录下的计划文档驱动本地开发流程。

## 触发条件

输入路径包含 `plans` 时自动触发

## 流程

### 1. 查找任务

读取 `docs/plans/<需求编号>/README.md`，找到第一个非 done 的任务。

### 2. 准备分支

从计划文档路径提取需求编号和任务名，创建本地分支：
- 示例：`docs/plans/UAC-123/01-用户列表.md` → `local/UAC-123-01-用户列表`

### 3. 检查未解决的问题

读取计划文档中的"未解决的问题"：
- **有问题**：输出问题描述，询问用户是否继续
- **无问题**：直接开始

### 4. 执行任务

1. 读取计划文档，在 local 分支上完善内容
2. 按 Todo 列表逐项执行
3. 每完成一项，更新计划文档中的 Todo 状态
4. 执行过程中可随时调整计划（修改 Todo、决策、约束等）
5. 可任意 `git commit`（存档点：`WIP: <简述>`）
6. **禁止推送 local 分支到 remote**

### 5. 遇阻塞处理

遇到阻塞时：
1. 在计划文档中填写"未解决的问题"（问题描述）
2. 提示用户当前阻塞点
3. 保留 local 分支，等待用户解决

### 6. 验收

- 所有 Todo 完成后通知用户验收
- 用户确认通过后继续步骤 7
- 如有问题，继续在 local 分支修复

### 7. 完成合并

```bash
git checkout feature/<需求编号>-xxx
git merge --squash local/<需求编号>-<任务名>
git commit -m "feat(<需求编号>): <任务汇总>"
git branch -D local/<需求编号>-<任务名>
```

### 8. 更新状态

- 计划文档：标记 `- [x] 已完成`
- README.md：更新计划分解表格状态为 ✅ 完成

### 9. 归档提示

检查 README.md，所有计划都完成后，提示用户可执行 `@vbp-archive` 归档。

## 异常处理

- **中途中断**：保留 local 分支，下次继续
- **合并冲突**：手动解决后 `git add` + `git commit`
