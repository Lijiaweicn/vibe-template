# VBW 逐项开发

按任务列表逐个开发，每个任务独立走 深化 → 开发 → 自检 → 验收 循环。

## 前置条件

`docs/feature/` 目录下存在已规划的需求文档（由 specify 生成）。

## 每个任务的执行流程

### 1. 定位与前置检查

1. 读取 `docs/feature/README.md`，找到第一个未完成的任务（`- [ ]` 状态）
2. 读取 README 头部的需求标识
3. 检查 `depends` — 前置任务未完成则提示用户
4. 检查"待解决" — 有待解决项则与用户逐一讨论，转化为 TODO 或已确定

### 2. 按需深化

**不强制提前深化所有任务。** 开发当前任务时，根据需要深入讨论：

- **技术方案讨论**：涉及哪些文件？需要新建/修改哪些 domain、component、view？
- **边界条件梳理**：空数据、加载态、错误态如何处理？
- **验收标准细化**：怎么判断"做完了"？细化验收清单为具体用户可见场景
- **依赖与风险**：依赖哪些接口/数据？有哪些已知风险？
- **设计决策质疑**：读取 `config.yaml` 的 `challenge-design` 插槽。skill 不为 null 时调用外部 skill；为 null 时内置质疑 — "为什么不是另一种做法？"

深化结果写回 task 文件（待解决、已确定、验收清单、TODO）。

### 3. TDD 开发

按 TODO 列表逐项执行。**默认采用 TDD 流程**：

1. 对第一个未完成的 `- [ ]` 项，执行红-绿-重构循环：
   - 🔴 **Red**：先写一个描述预期行为的测试，运行确认它失败
   - 🟢 **Green**：写最少的代码让测试通过
   - 🔵 **Refactor**：优化代码结构，保持测试通过
   - 标记为 `[x]`
2. 继续下一项，直到全部完成

**测试标准**：写测试时遵循 `.claude/rules/testing.md`（测试分级、BDD 风格、参数化测试要求）。

**TDD 豁免**：TODO 项可标记 `[no-tdd]` 跳过测试（如纯 UI 样式调整、配置变更、文档更新）。未标记的默认走 TDD。

**代码搜索**：查找已有模块、组件、接口时，优先使用 CodeGraph；不可用时回退到 Grep/Glob/Read。

开发过程中：
- **禁止自动 commit**，所有提交由用户手动控制
- 可调整 TODO 列表
- 遇到新问题可添加到待解决

**动态拆分子任务**：开发中发现需要拆分子任务时：
1. 新建 `<父slug>-<子slug>.md`（使用完整 task 模板）
2. 按需声明 depends
3. README 不必改动（除非新任务是大节点，需用户确认后加入 README）

### 4. 自检

所有 TODO 完成后：

**第一层：自检**（当前 agent 快速过一遍）

- [ ] 所有 TODO 项已标记 `[x]`
- [ ] 待解决已清空或全部转化为已确定
- [ ] 符合 `.claude/rules/code-reviews.md` 清单：
  - [ ] models 是纯函数（无 `this`、无响应式 API）
  - [ ] 常量已收拢到 `constants.ts` 并加了 `as const`
  - [ ] 表单场景：`formData` 不含 UI 属性（UI 属性已放 `uiContext`）
  - [ ] 视图模板：无复杂表达式（如 `v-if="a && b"`）
  - [ ] 视图模板：无可选链防御链（如 `data?.xxx`）

**第二层：交叉审查**（启动新 agent，干净上下文）

自检通过后，启动一个新的 agent 进行交叉审查：
- 注入干净上下文（无开发过程的历史对话）
- 提供 coding 规范（`.claude/rules/domains-code.md`、`.claude/rules/views.md`、`.claude/rules/code-reviews.md`）和本轮变更的文件列表
- 新 agent 处于"聪明区"，能发现因上下文疲劳而忽略的边缘 Bug
- 审查结果：通过 → 继续；有问题 → 修复后重新自检

### 5. 用户验收

读取当前任务的**验收清单**，逐项引导用户核验：

1. 展示验收清单（每项为 `- [ ]` 格式）
2. 用户逐项确认或反馈问题
3. 通过的项目标记为 `[x]`
4. 未通过的项目记录问题，回到步骤 3 修复

验收循环：
- 用户发现问题 → 修复 → 重新展示相关验收项
- 所有验收项通过 → 更新 README 标记任务完成，继续下一个任务

**重要**：验收以清单为准，不能跳过或笼统确认。

### 6. 循环

- **还有未完成任务**：回到步骤 1，继续下一个任务
- **所有任务完成**：进入 accept 阶段

## 暂停条件

出现以下情况时，暂停开发，回到 specify 补充任务文档：
- 需要新增大节点 task（改 README 任务列表 + 新建 task 文件）
- 当前 task 拆分不合理，需要拆分或合并
- 需求本身发生变化（背景、核心功能、验收标准）

## 门禁条件（单个任务完成的标准）

- [ ] 所有 TODO 项标记 `[x]`
- [ ] 待解决已清空或全部转化为已确定
- [ ] 自检 + 交叉审查通过
- [ ] 用户逐项验收通过

## 异常处理

- **中途中断**：保留当前进度，下次继续时从步骤 1 重新定位
- **需求变更/任务调整**：按暂停条件，回到 specify 补充文档后重新定位
- **依赖循环**：执行前检查 depends 是否构成循环依赖，如有则提示用户调整
