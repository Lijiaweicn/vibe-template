# VBW 逐项开发

基于任务文档驱动开发，在 feature 分支上按 TODO 列表逐项执行，默认采用 TDD。

## 前置条件

`docs/feature/` 目录下存在已规划的需求文档（由 specify + validate 生成）。

## 流程

### 1. 定位任务

读取 `docs/feature/README.md`，找到第一个未完成的大任务节点（`- [ ]` 状态的任务链接）。

读取 README 头部的需求标识，用于后续定位。

### 2. 检查依赖

读取任务文件的 frontmatter `depends` 字段：

- **有依赖**：逐一检查前置任务是否已完成（README 中对应项标记为 `- [x]`）
  - 前置任务未完成 → 提示用户先完成前置任务，询问是否切换到前置任务
  - 前置任务已完成 → 继续步骤 3
- **无依赖**：直接进入步骤 3

### 3. 检查待解决

读取任务文件的 **待解决** 部分：

- **有待解决内容**：
  1. 列出所有待解决项
  2. 与用户逐一讨论解决方案
  3. 讨论结果转化为 TODO 步骤，写入 **TODO** 部分
  4. 决策记录写入 **已确定** 部分
  5. 清空对应的待解决项
  6. 全部解决后进入步骤 4
- **无待解决内容**：直接进入步骤 4

### 4. 逐项开发

在当前 feature 分支上直接开发，按 TODO 列表逐项执行。**默认采用 TDD（测试驱动开发）流程**：

1. 读取当前任务的 TODO 列表
2. 对第一个未完成的 `- [ ]` 项，执行红-绿-重构循环：
   - 🔴 **Red**：先写一个描述预期行为的测试，运行确认它失败
   - 🟢 **Green**：写最少的代码让测试通过
   - 🔵 **Refactor**：优化代码结构，保持测试通过
   - 标记为 `[x]`
3. 继续下一项，直到全部完成

**TDD 豁免**：task 文件的 TODO 项可标记 `[no-tdd]` 跳过测试（如纯 UI 样式调整、配置变更、文档更新）。未标记的默认走 TDD。

**代码搜索**：查找已有模块、组件、接口时，优先使用 CodeGraph；不可用时回退到 Grep/Glob/Read。

开发过程中：
- **禁止自动 commit**，所有提交由用户手动控制
- 可调整 TODO 列表（添加/删除/修改步骤）
- 遇到新问题可添加到待解决

**暂停条件**：出现以下情况时，暂停当前任务开发，回到 specify 阶段补充任务文档：
- 需要新增大节点 task（改 README 任务列表 + 新建 task 文件）
- 当前 task 拆分不合理，需要拆分或合并
- 需求本身发生变化（背景、核心功能、验收标准）

**动态拆分子任务**：开发中发现需要拆分子任务时：
1. 新建 `<父slug>-<子slug>.md`（使用完整 task 模板），如父任务 `login-form.md` 的子任务命名为 `login-form-captcha.md`
2. 若新任务是当前任务的前置：当前任务的 `depends` 中加入新 slug
3. 若新任务是当前任务的后续：新任务的 `depends` 中加入当前 slug
4. README 不必改动（除非新任务是大节点，需用户确认后加入 README）

## 门禁条件

- [ ] 所有 TODO 项标记 `[x]`
- [ ] 待解决已清空或全部转化为已确定

## 异常处理

- **中途中断**：保留当前进度，下次继续时从步骤 1 重新定位
- **需求变更/任务调整**：按暂停条件，回到 specify 补充文档后重新定位
- **依赖循环**：执行前检查 depends 是否构成循环依赖，如有则提示用户调整
