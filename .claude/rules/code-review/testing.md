# 测试规则

## 严重等级

| severity    | 含义                     |
| ----------- | ------------------------ |
| blocker     | 确定会造成问题           |
| risk        | 高概率产生维护/运行风险  |
| improvement | 优化建议                 |
| uncertain   | 上下文不足，需要人工判断 |

## 3.1 测试优先级

测试优先级 = 业务影响 × 分支复杂度 × 复用范围。

| 优先级    | 条件                               | 无测试时              |
| --------- | ---------------------------------- | --------------------- |
| P0 必测   | 业务核心函数（权限、金额、状态机） | severity: blocker     |
| P1 建议测 | 有分支逻辑的工具函数               | severity: improvement |
| P2 可选   | 纯格式化、简单映射                 | 不输出                |

## 3.2 参数化测试

同类场景 ≥ 3 个 → 使用参数化测试（`it.each` / `describe.each`）。未使用 → severity: improvement。

## 3.3 测试命名

测试名必须包含：

- 被测行为（什么输入/操作）
- 预期结果
- **使用中文描述**

未包含被测行为或预期结果 → severity: improvement。
使用英文描述 → severity: improvement。

## 3.4 测试结构

遵循 Arrange-Act-Assert 分离。未分离 → severity: improvement。

## 3.5 不测内容

以下不需要测试：

- Vue 组件渲染（模板正确性）
- 第三方库本身的功能
- 纯类型定义
