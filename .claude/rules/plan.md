# Plan Rules

## 触发条件

新需求开发、架构改造、目录调整、数据模型变更、跨领域修改 → 必须生成规划文档。

## 文档目录

`docs/plans/<需求编号>/`（从分支名提取，如 feature/UAC-123-xxx → UAC-123）

## 文档结构

- **单任务需求**：`README.md`（直接写任务内容）
- **多任务需求**：`README.md`（总览）+ 多个 `01-xxx.md` 计划文档

## README.md 模板

```markdown
# <需求名称>[总览]

## 背景
<需求背景>

## 目标
<具体目标>

## [计划分解]  # 多任务时添加
| 编号 | 名称 | 状态 | 依赖 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| 01-xxx | xxx | ⏳ 待开始 | - | 描述 |

## 决策
<技术方案选择>

## 已确认
<接口、数据结构、页面结构>

## 约束
<限制条件>

## 涉及文件
| 文件/目录 | 操作 | 说明 |
| --------- | ---- | ---- |
```

## 计划文档模板（01-xxx.md）

```markdown
# <计划名称>

## 目标
<具体目标>

## 未确认
<信息缺失、需求歧义>

## 决策
<技术方案选择>

## 已确认
<接口、数据结构、页面结构>

## 约束
<限制条件>

## 涉及文件
| 文件/目录 | 操作 | 说明 |
| --------- | ---- | ---- |
```

## 禁止事项

- 不输出：函数实现、Class实现、Vue组件代码、API代码、SQL代码、Store代码
- 不生成超过 5 行的代码块
- 规划文档只记录设计决策，不记录实现细节
