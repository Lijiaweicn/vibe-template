# Plan Rules

## 触发条件

新需求开发、架构改造、目录调整、数据模型变更、跨领域修改 → 必须生成规划文档。

## 文档目录

`docs/plans/<需求编号>/`（从分支名提取，如 feature/UAC-123-xxx → UAC-123）

## 文档结构

- **大型需求（3+ plan）**：必须包含 `overview.md` + 多个计划文档
- **小型需求（1-2 plan）**：直接创建计划文档

## overview.md 模板

```markdown
# <需求名称> 总览

## 目标

<需求背景和最终目标>

## 计划分解

| 编号 | 名称 | 状态 | 依赖 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| 01-xxx | xxx | ⏳ 待开始 | - | 描述 |

## 变更文件汇总

（各计划完成后汇总）
```

## 计划文档模板（01-xxx.md）

```markdown
# <计划名称>

## 输入

<背景、目标>

## 未确认

<信息缺失、需求歧义、技术决策未确定项>

## 决策

<技术方案选择（无则省略）>

## 已确认

<接口、数据结构、页面结构>

## 约束

<限制条件>

## 涉及文件

| 文件/目录 | 操作 | 说明 |
| --------- | ---- | ---- |
```

## 禁止事项

- 不输出：函数实现、Class实现、Vue组件代码、API代码、SQL代码、Store代码
- 不生成超过 5 行的代码块
- 规划文档只记录设计决策，不记录实现细节

## 优先输出

表格、职责说明、目录结构、数据流、风险分析
