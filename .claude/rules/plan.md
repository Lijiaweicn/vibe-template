# Plan Rules

## 触发条件

新需求开发、架构改造、目录调整、数据模型变更、跨领域修改 → 必须生成规划文档。

## 文档目录

`docs/plans/<需求编号>/`（从分支名提取，如 feature/UAC-123-xxx → UAC-123）

如果没有编号，则取分支名称概括（如 feature/user-management → user-management）

## 文档结构

```
docs/plans/<需求编号>/
├── README.md            # 总览（背景、目标、计划分解表格）
├── 01-<计划名称>.md     # 具体计划内容
└── 02-<计划名称>.md     # 追加的计划（可选）
```

## README.md 模板

```markdown
# <需求名称>

## 背景

<需求背景>

## 目标

<具体目标>

## 计划分解

| 编号   | 名称 | 状态      | 依赖 | 说明 |
| ------ | ---- | --------- | ---- | ---- |
| 01-xxx | xxx  | ⏳ 待开始 | -    | 描述 |

## 决策

<技术方案选择>

## 已确认

<接口、数据结构、页面结构>

## 约束

<限制条件>

## 涉及文件

| 文件/目录 | 操作 | 说明 |
| --------- | ---- | ---- |
```

## 计划文档模板（01-xxx.md）

```markdown
# <计划名称>

## Todo

- [ ] 步骤1：xxx
- [ ] 步骤2：xxx
- [ ] 步骤3：xxx

## 未确认

<信息缺失、需求歧义>

## 决策

<技术方案选择>

## 已确认

<接口、数据结构、页面结构>

## 约束

<限制条件>

## 涉及文件

| 文件/目录 | 操作 | 说明 |
| --------- | ---- | ---- |

## 未解决的问题

（遇阻塞时填写，无则省略）
```

## 禁止事项

- 不输出：函数实现、Class实现、Vue组件代码、API代码、SQL代码、Store代码
- 规划文档只记录设计决策，不记录实现细节
