# 03 - 单元测试与自动化验证规范

## 一、 测试核心原则

测试的价值 = 逻辑复杂度 × 变更频率 × 影响范围。
你必须将精力集中在“多字段聚合规则”与“复杂显隐判定”上。

## 二、 测试分级与策略

- **P0（必须测）**：多字段聚合、`canSave`、`needApproval`、`uiContext` 的显隐分支。必须使用 **参数化测试 (`test.each`)** 减少样板代码。
- **P1（建议测）**：中等复杂的表单校验 `validateForm`。
- **P2/P3（严禁测）**：纯单项映射（如状态换文本）、业务枚举和常量。不需要为其浪费 Token 和时间。

## 三、 自动化闭环命令（Vibe 核心）

当你作为 AI Agent 接受指令并修改了任何 `models.js` 或 `index.js` 的逻辑后，**你必须无条件主动在终端运行 `npm run test` 或 `pnpm test`**。

- 如果测试未通过或出现 TypeScript 类型报错，**不允许向人类用户交付任务**。
- 你必须自行阅读终端报错，反复迭代修改代码，直至测试全绿、Lint 无报错后，方能提示人类用户查看结果。
